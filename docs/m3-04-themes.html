3.4 Themes and publication-ready figures

Control every non-data element, build your own theme, and export figures properly

NoteIn this lesson you will learn to
  • change the overall look with complete themes (theme_classic(), theme_bw(), …) and their base_size,
  • fine-tune any element with theme() and the element_*() functions,
  • save your settings as a reusable theme for all figures of a report or thesis,
  • export figures with ggsave() at the size and resolution journals require.

⏱️ About 35 minutes.

Complete themes

A theme controls everything that is not data: background, grid lines, fonts, legend position, axis lines. ggplot2’s default is theme_gray(). Other complete themes:

Notice that a plot can be stored in a variable (p) and extended later with +. That’s very handy for trying out styles.

theme_classic() (white background, axis lines, no grid) is the style most often seen in sport-science journals.

All complete themes have a base_size argument that scales all text. The default (11 pt) is often too small, especially for slides:

Fine-tuning with theme()

Add theme() after the complete theme to change individual elements. Each element is set with a matching element_*() function:

Element type Function Examples
text element_text(size, face, colour, angle) axis.title, axis.text, plot.title, legend.text
lines element_line(colour, linewidth, linetype) axis.line, panel.grid.major
boxes element_rect(fill, colour) panel.background, legend.background
remove element_blank() anything you want to hide

Plus some non-element settings, e.g. legend.position = "top" / "bottom" / "none" / c(0.8, 0.9) (inside the panel).

Starting from p (given), add theme_classic(base_size = 14) and then a theme() call that:

  1. moves the legend to the bottom,
  2. makes the axis titles bold (face = "bold").

base_size = 14, legend.position = "bottom", face = "bold".

p <- ggplot(squad, aes(x = body_mass_kg, y = jump_height_m, colour = sport)) + geom_point(size = 2) + scale_colour_manual(values = sport_cols) + labs(x = "Body mass (kg)", y = "Jump height (m)", colour = NULL) p + theme_classic(base_size = 14) + theme( legend.position = "bottom", axis.title = element_text(face = "bold") ) 
p <- ggplot(squad, aes(x = body_mass_kg, y = jump_height_m, colour = sport)) +
  geom_point(size = 2) +
  scale_colour_manual(values = sport_cols) +
  labs(x = "Body mass (kg)", y = "Jump height (m)", colour = NULL)

p + theme_classic(base_size = 14) +
  theme(
    legend.position = "bottom",
    axis.title = element_text(face = "bold")
  )

You write p + theme(legend.position = "none") + theme_classic(). The legend is still there. Why?

Order matters: complete themes reset everything. Always add the complete theme first, then your theme() tweaks.

Exporting figures with ggsave()

A figure for a journal or thesis must be saved at the right size and resolution. Don’t copy it from the RStudio Viewer: use ggsave().

my_plot <- ggplot(...) + ...

ggsave("figure1.png", plot = my_plot, width = 17, height = 10, units = "cm", dpi = 300)
ggsave("figure1.pdf", plot = my_plot, width = 17, height = 10, units = "cm")
ggsave("figure1.tiff", plot = my_plot, width = 8.5, height = 7, units = "cm", dpi = 600)
Setting Typical journal requirement
Width single column ≈ 8–9 cm, double column ≈ 17–18 cm
Resolution (dpi) ≥ 300 dpi for photos/plots, 600–1000 for line art
Format PDF/EPS/SVG (vector, sharp at any zoom) or high-res TIFF/PNG
TipSize first, then fonts

Text in a figure saved at 8.5 cm wide will look much bigger than in the same figure saved at 30 cm, because base_size is in points and doesn’t scale with the figure. Decide the final width first, save it, and check that the smallest text is still ≥ 7–8 pt at print size.

ggsave() runs here in the browser too, but the file is stored in the browser’s temporary file system, so you can’t open it. Try it in RStudio, where the file appears in your project folder.

Which format keeps a plot perfectly sharp at any zoom level?

Vector formats store shapes and text, not pixels, so they never get blurry. JPEG also adds compression artefacts around text and lines, so avoid it for plots.

Write a theme function theme_poster() for a conference poster. It should:

  1. start from theme_bw() with a base_size of 20,
  2. remove the minor grid lines (panel.grid.minor = element_blank()).

Then apply it to the plot on the last line.

base_size = 20, panel.grid.minor = element_blank(), and add theme_poster() to the plot.

theme_poster <- function() { theme_bw(base_size = 20) + theme(panel.grid.minor = element_blank()) } ggplot(squad, aes(x = sport, y = jump_height_m)) + geom_boxplot() + theme_poster() 
theme_poster <- function() {
  theme_bw(base_size = 20) +
    theme(panel.grid.minor = element_blank())
}

ggplot(squad, aes(x = sport, y = jump_height_m)) +
  geom_boxplot() +
  theme_poster()

A checklist for publication-quality figures

Before you submit a figure, check that:

A bar chart of mean jump heights (38 vs. 41 cm) has a y-axis starting at 37 cm, making one bar look three times taller than the other. What’s the problem?

For bar charts the length of the bar is the value, so the axis must start at 0. If you need to zoom, use points (e.g. mean ± SD with the raw data) instead of bars.

Lesson summary

  • Complete themes (theme_classic(), theme_bw(), …) set the overall look; base_size scales the text.
  • theme() + element_text() / element_line() / element_rect() / element_blank() fine-tune elements. Add it after the complete theme.
  • Store your style in a function (theme_lab <- function() theme_classic() + theme(...)) and reuse it.
  • Export with ggsave(file, plot, width, height, units = "cm", dpi = 300); prefer vector formats.
